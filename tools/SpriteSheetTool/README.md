# Sprite sheet export

Package-free Windows C# tool (.NET 10). Run from the repository root:

Build the repository copy with `dotnet build tools/SpriteSheetTool`. Run its disposable filesystem regression checks with `pwsh -File tools/SpriteSheetTool/SelfTest.ps1`. The tests cover both grid and component modes, PNG/JSON/contact/archive collisions, primary/row-map inputs, normalized aliases, source hash preservation and real relative source links.

Reproduce the selected set with `pwsh -File tools/SpriteSheetTool/Export-All.ps1`. The source archive contains12 selected/historical PNGs. Hero export uses cell anchors, a64×64 content box at(0,8), and fixed per-source scales from its row map; unit exports retain body anchors. Add `-HeroOnly` to rewrite only the hero PNG/JSON/contact sheet while verifying all six atlases and checking that five unit PNGs, JSON sidecars and contact sheets keep their SHA256 hashes. HeroOnly leaves the gallery manifest and HTML unchanged.

All input/output paths are preflighted before any write. Export PNG, JSON sidecar, contact strip and source archive must be distinct and must not alias the primary source, row-map file or any row-map image. Windows case, dot segments, junction/symlink paths and existing-file identity are checked. `--source-copy` identical to the primary source path is an explicit no-op; a different alias to that input is rejected. Without `--source-copy`, `source.image` still resolves to the actual original input relative to the sidecar.

```powershell
dotnet run --project tools/SpriteSheetTool -- --source C:/path/generated.png --output content/art/animations/hero.flora.walk.png --kind hero --id hero.flora.walk --source-copy docs/art/sources/hero.flora.walk.source.png
```

For generated atlases whose gutters do not follow an exact grid, add `--components --alpha-cutoff 128 --align-bottom 72`. This opt-in mode analyzes the entire input before any cropping: eight-connected alpha-mask components; main figures require area>=10% of nominal cell area and height>=35% of nominal cell height. Their centers assign the intended row/column. Wrong main counts or duplicate frame assignments stop export; bodies are never split, repainted, or automatically repaired.

Detached effects attach to the closest main bounding box. Ties use distance between actual boundary pixels. Ambiguous attachments are reported; effects farther than30% of the larger nominal cell dimension are reported and left unassigned. Complete component groups are unpacked, so source rectangles may overlap geometrically without borrowing pixels from another figure. Sampling retains RGB exactly and produces binary alpha.

The component mode uses one constant scale per source path, calculated across all its series frames to fit the maximum group extents around the fixed ground pivot inside the content box. The pivot is the mean X of primary-body pixel centers in its lower15%; the primary body's exclusive bottom maps to72. This accounts for a club or effect extending farther on one side; it can require a smaller scale than width/max-bbox alone. Every frame changes only translation. A final integer vertical correction places the sampled primary body's bottom exactly on the baseline. No effect controls the foot height. JSON records source hashes/counts, main/effect component IDs, original group/body crop bounds, fixed scale, pivot/offset, native bounds and both native/source clipping counts. Gallery highlights unpacking counts and clipping rather than treating resolved historical source-grid cuts as current failures.

For walk cycles with intentional moving feet, opt into `--anchor-mode cell`. Default `body` keeps the behavior above. Cell mode fixes source X to `(column+0.5)*sourceCellWidth` and source Y to the maximum primary-body bottom across the entire source row. It applies no per-frame bottom correction (`translationY=0`), preserving the source's relative torso/feet positions. Safe source scale uses these fixed pivots and full group bounds. `anchorMode`, `pivotX`, `pivotY`, actual sampled/registered bottoms and offsets are recorded truthfully; a raised foot can end above72. Run `pwsh -File tools/SpriteSheetTool/AnchorModeSelfTest.ps1` to verify a fixed torso does not follow moving feet and that offsets remain constant within a row.

Opt-in `--hero-two-frame` requires `--components --kind hero`. Input/source row maps remain six columns; output is two columns×nine rows (128×720). Each walk row samples source columns0 and3 into a two-frame220ms loop. Idle samples source column0 into both final slots, but its nonlooping clip references only slot16; slot17 is unused. Bind idle row8 to the same SE-walk source row0/scale as walk row3. This gives18 physical slots and17 used frames. SourceFrame/sourceColumn/sourceRow provenance and full-source RowGrounds remain explicit; unselected source frames still influence the common row anchor. Default hero six-frame and unit behavior is unchanged. Run `pwsh -File tools/SpriteSheetTool/HeroTwoFrameSelfTest.ps1` for the contract/provenance fixture. Export-All now requires this approved row map and verifies74 total physical slots across all six atlases.

`hero`: 6 columns × 9 rows, N/NE/E/SE/S/SW/W/NW/IdleSE, six frames per clip, 110 ms per frame by default. `unit`: 4×2, eight attack frames. `support`: 4×4, eight attack then eight ability frames. Unit defaults are 100 ms per frame and zero-based impact frame 4. Override with `--frame-ms` and `--impact-frame`. Clip frame indices are zero-based row-major; `impactFrame` is a zero-based index within its clip. Attack and ability clips are marked non-looping for consumers; the review gallery intentionally repeats them.

Native cells are always 64×80 with a fixed logical foot anchor (32,72). Source cell bounds use the proportional grid, even when source dimensions do not divide evenly. Every entire source cell receives the same uniform contain scale into a fixed per-asset content box, preserving aspect ratio; horizontal alignment is centered and vertical alignment is bottom. Default `--content-box 8,8,48,64` suits hero/thin units. Use `--content-box 8,16,48,56` for the smaller squash body. Sampling chooses integer source pixels by nearest neighbor. There is no silhouette detection, per-frame crop, color replacement, smoothing, or automatic anchor correction. Generated artwork must already maintain a common foot position and adequate cell margins; inspect that against the gallery anchor.

Optional `--alpha-cutoff 128` creates hard-edge binary alpha: sampled A<128 becomes0; A>=128 becomes255. Sampled RGB channels are unchanged, including RGB stored beneath alpha0. This is a fixed alpha threshold, with no chroma key, palette operation, filter, or per-frame decision. Omit the argument to preserve alpha. The sidecar records the threshold and content box. Tiny effects whose alpha is below the threshold become transparent; visually review the exported loops.

Optional `--align-bottom 72` registers each already-scaled, already-thresholded frame by integer vertical translation only. It finds the nontransparent bounding box and moves its exclusive bottom edge to72; scale, width, colors and pose remain unchanged. Use sources without lower shadows/effects because this is a whole-art baseline, not semantic foot detection. Metadata `registration` records each frame's original bottom, translation, final bottom and any clipped visible pixels. A translated-clipping warning reports losses explicitly. This is an intentional opt-in exception to otherwise fixed placement; it never changes frame scale or performs tight cropping.

`sourceBorderDiagnostics` counts visible source pixels on each original proportional cell border (using the selected alpha threshold). A source-border warning can reveal effects extending into another frame even when the final native-cell margin is clear. Counts do not prove that neighboring pixels belong to the wrong frame; inspect the source. `--contact-strip path.png` writes a separate 2× review grid with frame borders, baseline, frame index, translation and `SRC!` flags. The strip is a diagnostic overlay, not a gameplay texture. `--ability-name heal` or `--ability-name conversion-hit` names the second eight-frame support clip.

The PNG sidecar JSON includes clips, timing, dimensions, anchor, source hash, alpha counts, original cell bounds and the exact common transform. Per-frame diagnostics report visible bounds and pixels touching cell borders; empty/edge-touching frames produce a review warning. `--source-copy` archives the actual input, unchanged. Fully opaque sources are rejected as possible fake transparency; `--allow-opaque` is an explicit review escape hatch, never background removal. Mixed fake transparency still needs visual review.

To replace selected rows from another generated sheet, pass `--row-map rows.json`. The JSON is an array, for example `[{ "source": "hero-second-source.png", "sourceRow": 2, "targetRow": 4, "sourceColumns": 6, "sourceRows": 9 }]`. Source paths are relative to the map file (or absolute). Rows are zero-based. Unmapped rows use the primary source. A mapped source must have the same number of columns; its row count may differ. Each source uses its own common proportional-grid contain transform, with no individual-frame adjustment. Archive secondary sources explicitly before export; metadata records their relative paths, grid dimensions, selected rows and hashes. Inspect scale and ground alignment across source transitions.

In component mode, a row-map entry may include `"sourceScale": 0.0959` to match the established body size of another atlas. This is one absolute uniform scale for that entire source path; all entries for the path must agree. Values above the computed safe fit scale are rejected. JSON records both the automatic `FitScale` and chosen `Scale`. This only permits a conservative global reduction, never per-frame resizing.

Add each exported JSON path to `docs/art/animations/manifest.json`, relative to that file, for example `../../../content/art/animations/hero.flora.walk.json`. Serve the repository root with a local HTTP server and open `/docs/art/animations/`. The dependency-free gallery provides 2× nearest-pixel clip playback, pause, previous/next frame, restart, speed, four backgrounds, source/JSON links and full-sheet inspection. It has no gameplay integration.
