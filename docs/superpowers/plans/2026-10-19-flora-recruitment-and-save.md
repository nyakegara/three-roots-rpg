# Места найма, ограниченные запасы и сохранение: план реализации

> **Для исполнителей:** использовать `superpowers:subagent-driven-development` для задач по очереди, с независимым ревью после каждого завершённого изменения. Шаги отмечаются чекбоксами.

**Цель:** привязать три места найма к точкам карты, обеспечить конечные запасы, атомарную покупку и сохранение остатков кампании.

**Архитектура:** `CampaignLoader` проверяет файлы и связи карты с кампанией; `Campaign` владеет runtime-состоянием мест; `EconomyRules` атомарно списывает золото и запас; `CampaignSerializer` хранит остатки по стабильным ID.

**Технологии:** C#, .NET 10, xUnit, `System.Text.Json`; существующая схема сохранения версии 1 из ветки `feat/campaign-persistence` расширяется без миграции старого формата.

**Спецификация:** `docs/superpowers/specs/2026-10-19-flora-roster-and-recruitment-design.md`.

## Общие ограничения

- Три точки карты с ID `root-greenhouse`, `sunny-clearing`, `spore-circle` дают по одному месту найма.
- Предложение хранит остаток в количестве бойцов; найм `N` списывает ровно `N`.
- Репутация изменяет цену, но не доступ к предложению.
- Любой отказ оставляет без изменений золото, армию и остаток запаса.
- Сохранение версии 1 содержит одну запись на каждую пару ID места и типа войска, включая нулевой остаток.
- Карта остаётся JSON 8×7; новые точки размещаются на проходимых клетках и не требуют переделки ландшафта.

## Риски и фокус ревью

- Дублированный/неизвестный site ID либо несопоставленная точка блокирует загрузку; задача 2.
- Нулевая или отрицательная цена/запас не принимается; задача 1.
- Неудача покупки из-за денег, запаса или вместимости не меняет ни одно состояние; задача 1.
- Сохранение с отсутствующим, дублированным или неизвестным остатком не применяется частично; задача 3.
- Несовместимость ID старого JSON-контента исключается сохранением стабильных ID типов флоры; задачи 2 и 3.
