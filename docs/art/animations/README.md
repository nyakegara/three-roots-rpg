# Анимации войск — набор для проверки

Откройте `preview.html` двойным щелчком: PNG и разметка встроены в HTML, сервер и интернет не нужны. Пауза, шаг вперёд/назад, скорость и четыре фона помогают проверить силуэт, прозрачность и стык последнего кадра с первым. Красная отметка обозначает опору. Ссылки на исходники и контактные листы работают рядом с остальными файлами репозитория.

Это подготовленные ресурсы. MonoGame использует одиночные спрайты войск, включая новых людей; подключение проигрывателя клипов атак остаётся отдельным изменением после просмотра графики.

## Формат

Все игровые PNG находятся в `content/art/animations`. Размер клетки **64×80**, опора **(32,72)**, прозрачность только 0/255. Просмотр — в масштабе 2× без сглаживания. Нумерация кадров начинается с нуля, слева направо, затем сверху вниз. JSON рядом с PNG содержит размеры, индексы, длительность кадров, признак цикла и момент применения действия.

Всего 191 используемый кадр и 40 клипов, включая трёх героев. У каждого героя 36 ячеек, из которых используются 29; остальные — технические дубликаты для прямоугольной сетки. В N/S две контактные позы по 220 мс. В остальных направлениях четыре позы по 110 мс: контакт одной ноги → ноги под корпусом → контакт другой ноги → ноги под корпусом. Полный цикл в обоих случаях длится 440 мс. Покой содержит ровно один индекс и не анимируется. Юниты: 100 мс/кадр; `impactFrame=4` — пятый кадр внутри действия. Атаки и способности разовые, хотя галерея намеренно повторяет их для проверки. Обращение гриба — эффект удачного срабатывания после выстрела, не новая активная способность. Анимаций ходьбы юнитов нет.

## Подготовка и воспроизводимость

Исходники генерации сохранены без изменений в `sources`, карты замены строк — рядом с ними. Три исходных листа героя оставлены для истории; текущие источники ходьбы: N/NE/E, SE и S/SW/W/NW. N/S используют столбцы 0/3 источника; остальные направления — 0/1/3/4. Для покоя используется отдельный одиночный `hero.idle.source.png`: это неизменённая копия исходного `content/art/hero.flora.png` с нейтральной стоячей позой, а не замерший кадр шага. Для Ипомеи лечение заменено отдельным листом, чтобы посох оставался во всех кадрах. Остальные юниты используют по одному источнику.

Изображения распаковываются по связным непрозрачным компонентам: исходная генерация не соблюдала идеальную сетку. C#-инструмент собирает цельные фигуры с их эффектами и применяет единый масштаб для каждого исходника. Цвета берутся из исходника без фильтрации; альфа ниже 128 отсекается. Размер каждой позы отдельно не подгоняется. Для нового лечения Ипомеи явно задан общий масштаб 0.0959, согласованный с атакой.

Герой экспортируется с `--anchor-mode cell`: центр исходной ячейки по X и общая линия земли для всей строки по Y. Опора больше не следует за перемещающимися стопами; отдельные кадры не сдвигаются к линии земли. Видимая нижняя граница может быть 71 или 72, логическая опора остаётся (32,72). Высота силуэтов 55–57 пикселей; область размещения героя расширена до 64 пикселей, чтобы широкий шаг не уменьшал всю фигуру. Юниты сохраняют прежний режим `body` и прежние PNG/JSON.

Регрессионный тест `tools/SpriteSheetTool/AnchorModeSelfTest.ps1` проверяет неподвижный корпус при смене положения ног. Тест компактного режима проверяет разные длины клипов, выбор столбцов 0/1/3/4 и одиночный источник нейтральной позы. Это проверки экспортёра, а не доказательство качества нарисованной походки: позы оцениваем отдельно по стопам и коленям.

Из корня репозитория в PowerShell 7:

```powershell
pwsh -File tools/SpriteSheetTool/Export-All.ps1
pwsh -File tools/SpriteSheetTool/Export-Humans.ps1
pwsh -File tools/SpriteSheetTool/Build-Preview.ps1
```

Для обновления только героя используйте `Export-All.ps1 -HeroOnly`: остальные пять атласов остаются без записи, но их пиксели также проверяются.

Первый скрипт пересобирает PNG, JSON и контактные листы из архивных источников. Второй обновляет переносимый просмотр. `index.html` — та же галерея с загрузкой файлов через HTTP для разработки. Подробности экспортёра и проверки путей: `tools/SpriteSheetTool/README.md`.

Оценивать художественно нужно смену ведущей ноги, промежуточное положение стоп под корпусом и положение корпуса. Виды N/NE/NW сложнее оценивать: плащ частично скрывает ноги. Изменения плаща сами по себе не считаются шагом. Покой должен выглядеть устойчивой стоячей позой. Также проверяем форму рук/посоха на поворотах и возврат атак в покой. Автоматические проверки не заменяют эту оценку.
