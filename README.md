# Три корня

Курсовой проект: пошаговая RPG на C# и MonoGame, без игрового движка. Игрок исследует отдельные карты-кампании, принимает решения в заданиях и сражается на гексагональном поле.

## Требования

- .NET 10 SDK
- Windows, Linux или macOS для запуска MonoGame DesktopGL

## Сборка и запуск

Из папки репозитория:

```powershell
dotnet restore ThreeRoots.sln
dotnet build ThreeRoots.sln
dotnet run --project src/Game.MonoGame/Game.MonoGame.csproj
dotnet test ThreeRoots.sln
```

## Структура

- `src/Game.Core` — правила и модели игры; проект не зависит от графической библиотеки.
- `src/Game.MonoGame` — окно, ввод и отрисовка.
- `tests/Game.Tests` — автоматические проверки правил.
- `content` — кампании, карты и изображения.
- `docs/superpowers` — согласованный дизайн и план реализации курсовой.

## Сохранения и рекорды

`CampaignSave` хранит только изменяемый прогресс и стабильные ID: состояние героя, координату, армию, завершённые задания и выбранные варианты. Описания существ, навыков и артефактов остаются в JSON-контенте. Поле `SchemaVersion` понадобится для будущих изменений формата.

`CampaignSerializer.Save` записывает JSON во временный файл рядом с целевым и только после успешной записи заменяет сохранение. `Load` проверяет версию, обязательные поля и согласованность выбранных вариантов с завершёнными заданиями; результат включает понятное сообщение об ошибке.

`LeaderboardStore` ведёт независимые списки по `campaignId` и оставляет десять лучших результатов. Новый рекорд добавляется атомарной заменой JSON-файла, а повреждённый файл приводит к `InvalidDataException`, чтобы не затереть старые результаты. Игровые события пока не подключены к автосохранению; точки сохранения добавим при интеграции кампании в игровой цикл.

## Git для этого проекта

`git status` показывает, какие файлы изменились; `git add <файл>` выбирает изменения для коммита; `git commit -m "описание"` сохраняет их в локальной истории; `git push` отправляет коммиты на GitHub. Перед каждым коммитом запускай `dotnet test ThreeRoots.sln` и проверяй `git status`.

## Модель карты

- `HexCoord` хранит axial-координаты гекса, находит шесть соседей и считает расстояние.
- `WorldTile` описывает клетку: координаты, высоту (от нуля) и проходимость. Свойства задаются при создании и затем не меняются.
- `WorldMap` хранит клетки в словаре по координатам. `Contains` проверяет наличие клетки, `GetTile` возвращает клетку или `null`, `Tiles` позволяет перечислить клетки.

Форму карты задаёт набор существующих клеток: допустимы отрицательные координаты и пустые участки. Непроходимая клетка остаётся частью карты. Повторяющиеся координаты отклоняются; изменения исходного списка клеток не меняют созданную карту.

## Исследование и экран боя

`BattleMap` хранит рельеф боевого поля. `AStarPathfinder` находит кратчайший путь по существующим проходимым гексам; занятые клетки передаются отдельно. Маршрут включает старт и цель, а его стоимость равна количеству шагов. Если пути нет, `IsReachable` равен `false`, список клеток пуст.

В A* приоритет клетки — сумма уже пройденного пути и оценки расстояния до цели. Препятствия могут увеличить реальный путь, но гекс-расстояние никогда его не завышает. При одинаковых оценках используется стабильный порядок направлений.

Обычный запуск открывает кампанию из `content/campaigns/flora-01.json` и её карту `content/maps/flora-01.json`: луг, лес, холмы, воду, героя, квесты и места найма. Обзорная карта прокручивается, когда курсор подходит к краю её области; нижняя деревянная панель остаётся на месте. В исследовании нет видимой гекс-сетки:

![Карта исследования без боевой гекс-сетки](docs/screenshots/exploration.png)

При наведении на квест нижняя панель показывает его имя и действие:

![Наведение на квестовую точку и подсказка в HUD](docs/screenshots/exploration-quest-hover.png)

- Наведение показывает имя и действие для квеста или тайника в нижней панели.
- Первый клик ЛКМ по цели показывает путь; повторный клик по той же цели перемещает героя. ПКМ не перемещает.
- `E` осматривает точку под героем; `Esc` закрывает игру.

### Пробный бой против ИИ

```powershell
dotnet run --project src/Game.MonoGame/Game.MonoGame.csproj -- --combat
dotnet run --project src/Game.MonoGame/Game.MonoGame.csproj -- --combat --seed 42 --night
```

Отдельный пробный бой: пять стеков флоры против трёх стеков людей. Характеристики загружаются из `content/units/units.json`. Золотой гекс отмечает активный отряд; значки внизу показывают инициативу, числа возле существ — численность. У людей временно один спрайт стража для всех трёх видов: О — ополченец, К — копейщик, Л — лучник. Наведение показывает полное имя и здоровье.

- ЛКМ по свободному гексу показывает маршрут; второй клик по той же клетке подтверждает движение в пределах запаса хода. Зелёный контур отмечает доступные клетки. ПКМ не двигает.
- ЛКМ по доступному врагу атакует. За активацию разрешены одно перемещение и одна атака либо лечение, в любом порядке. `Enter` завершает ход; ИИ выполняет действия с небольшой паузой.
- `H` у Ипомеи включает лечение: затем ЛКМ по другому живому раненому союзнику. Восстанавливается 10 суммарных ОЗ, максимум до здоровья стека в начале боя; численность может восстановиться. Полностью погибший стек не лечится.
- Гриб после попадания с вероятностью 1/8 обращает выживший вражеский стек на сторону игрока до конца боя. В постоянную армию чужой стек не добавляется.
- `G` переключает сетку, `N` — дневное/ночное освещение; `Esc` закрывает игру. После победы или поражения видны потери; `R` повторяет тот же бой.

Это песочница: результат не меняет армию кампании. Встречи на карте, постоянные потери и награды ещё не связаны с этим экраном. Ответных ударов и анимации выстрела пока нет.

`Battle` проверяет команды и хранит здоровье/очередь. `BattleInteraction` подтверждает путь и передаёт управление между игроком и ИИ без зависимости от MonoGame. `BattleScreen` обрабатывает мышь, клавиатуру и паузу ИИ; `BattlefieldRenderer` рисует рельеф одинаково в игре и прежнем прототипе; `BattleHud` рисует панель команд. Новые библиотеки для боя не нужны.

Для реальных кадров используются `--screenshot-combat`, `--screenshot-combat-night`, `--screenshot-combat-heal`, `--screenshot-combat-result` с абсолютным PNG-путём. Состояния лечения и результата достигаются законной симуляцией команд; для воспроизводимых кадров используйте seed 1729. На произвольном поле кадр лечения может оказаться недостижим, и захват явно сообщит об этом.

Боевой предпросмотр `--battle` сохранён отдельно для проверки генерации, высоты и освещения без атак и ограничения движения.

### Генерация боевого поля и освещение

```powershell
dotnet run --project src/Game.MonoGame/Game.MonoGame.csproj -- --battle
dotnet run --project src/Game.MonoGame/Game.MonoGame.csproj -- --battle --seed 42 --night
```

В предпросмотре `F5` создаёт следующее поле, `R` возвращает героя на старт текущего поля, `G` включает/выключает сетку, `N` плавно меняет день и ночь. Для движения нужны два клика ЛКМ по одной цели: сначала маршрут, затем подтверждение.

`BattlefieldGenerator` создаёт поле 12×8 гексов. Несколько холмов дают высоты 0–2 с плавными соседними перепадами. Камни перекрывают движение и линию выстрела, брёвна — только движение, кусты служат проходимой декорацией. После размещения каждого препятствия обход клеток проверяет, что все проходимые гексы остались связаны. Стартовые полосы обеих сторон свободны и ровные. Одинаковый `--seed` воспроизводит высоты и расположение предметов; время суток их не меняет.

Генератор и данные поля относятся к `Game.Core`, а рисунки предметов, фон и палитра — к `Game.MonoGame`. День и ночь меняют представление сцены; урон, дальность, правила движения и характеристики не изменяются. Подсветка интерфейса и тактические подсказки остаются читаемыми.

Собственные рисунки можно добавлять по инструкции `content/art/README.md`, сохраняя имена файлов. Для реального PNG-кадра из приложения можно передать абсолютный путь:

```powershell
dotnet run --project src/Game.MonoGame/Game.MonoGame.csproj -- --screenshot C:\Temp\three-roots-preview.png
dotnet run --project src/Game.MonoGame/Game.MonoGame.csproj -- --screenshot-quest-hover C:\Temp\three-roots-quest-hover.png
```

Обычный запуск и `--screenshot` показывают карту исследования. `--screenshot-quest-hover` показывает наведённый квест и его действие в HUD. `--screenshot-grid` сохраняет сгенерированное поле, а `--screenshot-grid-descent` — прежнее фиксированное поле для проверки спуска. Любой режим скриншота сохраняет кадр и закрывается; обычный запуск остаётся интерактивным.

Для сравнения одного поля днём и ночью:

```powershell
dotnet run --project src/Game.MonoGame/Game.MonoGame.csproj -- --screenshot-grid C:\Temp\battle-day.png --seed 1729
dotnet run --project src/Game.MonoGame/Game.MonoGame.csproj -- --screenshot-grid C:\Temp\battle-night.png --seed 1729 --night
```
